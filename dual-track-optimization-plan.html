Dual-Track Research Agent Optimization

Autoresearch-style loop for Claude Code research plugin · March 2026 · ESP32-S3 Benchmark

This system iteratively improves research agent instructions by running a loop: edit the agent's instruction file, run a benchmark research task, score the output, and keep or discard the change based on whether the score improved. Two parallel optimization tracks target different agent types.

The benchmark uses real ESP32-S3 documentation cached locally for deterministic, repeatable scoring. No synthetic data.

How It Works

RoleWhoWhat They Do
OptimizerYour main Claude Code conversation (Opus)Decides what to change in the instruction file, makes the edit, runs the benchmark, reads the score, decides keep/discard
Test SubjectFresh agent spawned each experiment (Haiku or Sonnet)Receives the modified instructions, processes benchmark sources, outputs structured JSON
Judgescore.py (Python script, no LLM)Reads the JSON output, compares against rubric of expected findings, outputs a composite score 0.0–1.0
edit instruction file → git commit → spawn agent → score output → keep or discard → repeat forever
No optimization loops will run until explicitly triggered. This plan only builds the infrastructure.

Scoring Dimensions

DimensionWeightWhat It Measures
Finding Recall25%Did the agent find the expected facts? (string match against rubric fragments)
Verbatim Quality20%Are excerpts actually copied from the source? (substring comparison)
Category Coverage15%Findings spread across all core categories?
Precision15%Are findings well-formed with all required fields?
Cross-References10%Did it identify relationships between sources?
Gap Detection10%Did it identify missing information?
Structure Quality5%Valid JSON with correct schema?
All scoring is deterministic Python — no LLM involved in judging. Same script for both tracks.

Audit Fixes (Applied to Shared Infrastructure)

score.py Fixes

Placeholder detection: regex instead of startswith("[") — was catching markdown links and JSON arrays
Category coverage: exact match instead of bidirectional substring — was inflating scores
Verbatim window: max(5, ...) floor — short excerpts could pass by coincidence
New: cross-reference and gap scoring functions

optimize.md Fixes

Resume protocol — recover state from results.tsv after conversation crash
Inline JSON schema — don't rely on agent reading another file
3-minute experiment timeout — kill hung agents
Crash retry logic — retry once if fixable, then revert
Source pre-check — verify benchmark files exist before starting
Rewind guidance — 15+ consecutive discards triggers revert to best
Plateau detection — 10 consecutive discards triggers radical changes
Baseline logging — explicit first entry in results.tsv

Verification Checklist

  1. Cached sources exist in benchmark/sources/esp32s3/ with real content (>1KB each)
  2. Rubric has 25-30 expected findings with specific verbatim excerpt fragments
  3. python3 score.py scores all 7 dimensions correctly on test JSON
  4. Solo Haiku baseline: spawn agent, score output, verify reasonable baseline (expect 0.4–0.6)
  5. Solo Sonnet baseline: spawn agent, score JSON + synthesis, verify scorer works
  6. Run 3 experiments on each track manually to confirm loop works end-to-end
